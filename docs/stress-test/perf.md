## 测量基线 Benchmark

> 平台：**i5-1235U**（12 逻辑线程）/ 15GB / Fedora 44
> CPU 被 powersave 锁频（~1.9GHz，上限 4.4GHz），绝对值偏低，但同条件对比的比率有效

### wrk 命令

> 推荐配比：**wrk `-t6` + http_server `--threads 6`**（最均衡，避免同机客户端抢占）

```bash
wrk -t6 -c100 -d30s http://127.0.0.1:8080/index.html
wrk -t6 -c400 -d30s http://127.0.0.1:8080/index.html
```

> 目标文件 `app/index.html`（9KB），同一机器、同一 wrk 参数对比 http_server 与 nginx

### 对比数据

> http_server 三档：默认 / `-L warning` / A1+`-L warning`。锁频下绝对值跨会话不可比，同会话内两服务同频率，比率有效

| 并发 | 默认 | `-L warning` | A1+`-L warning` | nginx | 最高比率 |
|:---:|:---:|:---:|:---:|:---:|:---:|
| c100 | 121,963 | 151~169k | 173,585 | 330,128 | 52.6% |
| c400 | 117,256 | 141,710 | 137,834 | 287,854 | 47.9% |

### 线程配比对照

> 同机 wrk 客户端与服务端线程抢占，wrk 线程多于服务端时系统性低估服务端能力；t6/t6 最接近真实能力

| wrk / 服务线程 | http_server c100 | c400 | nginx c100 | c400 | 比率 c100 | c400 |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 8 / 4 | 173,585 | 137,834 | 330,128 | 287,854 | 52.6% | 47.9% |
| **6 / 6** | **199,092** | **166,458** | 333,206 | 291,274 | **59.7%** | 57.2% |
| 4 / 4 | 179,722 | 163,814 | 334,581 | 263,147 | 53.7% | 62.3%\* |

> \* t4/t4 的 c400 含 nginx 锁频拖低虚高；三组测试 CPU 频率不同（8/4@2.9G / 6/6@1.8G / 4/4@1.2~1.9G），**方向性结论可信**

**隔离测试（t6/t6，两服务器不同时运行）**：

| 服务器 | c100 | c400 |
|:---:|:---:|:---:|
| http_server 单独 | 199,579 | 165,787 |
| nginx 单独 | 308,786 | 282,183 |
| **比率** | **64.6%** | **58.8%** |

> 隔离与共存下 http_server 吞吐几乎一致（nginx 空闲不抢 CPU）；比率升高主因 nginx 单跑波动，非隔离提升

### 已完成的优化

- **warm 路径免 statx**：路径解析缓存，命中零系统调用，c100 +28% / c400 +38%
- **缓存 shared_ptr 零拷贝**：`lru_cache` 存 `shared_ptr` + `shared_string_body`

## 优化清单 Optimization

### A

- [x] **缓存 key 免临时 string 分配**：`get()` 传引用 + `path_cache_` 改 `std::map` 异构查找，每请求省 2 次堆分配
- [x] **请求日志成本量化**：`-L warning` 关访问日志，c100 +38% / c400 +21%（访问日志拖慢 25~38%）

### B

- [x] **ETag/Last-Modified + 条件 GET**：304 空 body，warm 命中零系统调用
- [ ] **sendfile 大文件零拷贝**：大文件质变，9KB 小文件 ~0 收益，服务大文件需求真实才做
- [ ] **P 核绑定**：Alder Lake P+E，先 `taskset` 实验验证
- [ ] **socket 缓冲调优**：仅大文件/高 BDP 有效；OS 上限调整是平台级、不随代码走

### C

- [ ] asio executor 拷贝削减（~5.3%）：架构级重写
- [ ] SO_REUSEPORT 多 accept 队列：高并发才有效
- [ ] C++20 协程重写：非吞吐必需，仅学习价值

-----

## 结论 Conclusion

- 已实现：warm 避免 statx、缓存零拷贝、缓存 key 免分配、访问日志可关、ETag/304
- 最大单项收益：免 statx（c100 +28% / c400 +38%）
- 实测：隔离测试约 nginx 的 60%，与 Node cluster 同级
- 未做项按需推进（见 B/C）
